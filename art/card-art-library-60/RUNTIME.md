# Runtime card art integration

The approved 60-image library supplies 120 additive runtime IDs:
`assets/cards/library/<category>-<type>-<01..05>-<512|1024>.webp`.
Categories are physical and magical; types are attack, smash, counter, evade,
sweep and defend. The source revision was approved at
`493b805263b5d80f502cd3328b3a34445885913e`.

`runtime-assets.json` maps each ID to its source export and PNG master hash.
The original authoring `manifest.json` is preserved verbatim; its `status` and
`scope` describe the earlier source approval stage. This runtime receipt and the
root `art-manifest.json` describe the subsequent runtime integration.
The high files are exact copies of the source WebPs, at 512 by 768 and
1024 by 1536 pixels. The PNG masters, original prompts, revision history and
source exports remain under `art/`, outside the three runtime ZIPs.

The light images are generated with the existing default policy: maximum edge
720, quality 50 and alpha quality 50. Both filename sizes therefore have
480 by 720 light twins. The first integration used cwebp 1.6.0. Existing high,
light and common files and their provenance remain unchanged. Old artwork stays
available at its existing IDs; no card definitions or mechanics are added here.

Run from a checkout containing the full `hd/`, `light/` and `common/` trees:

```sh
node tools/card-art-library.mjs
node tools/mobile-art.mjs
node tools/manifest.mjs --write
node tools/card-art-library.mjs --check
node --test tests/*.test.mjs
node tools/mobile-art.mjs --selftest
node tools/manifest.mjs --check
node tools/mobile-art.mjs --check
node tools/pack.mjs --check
```

The first tool validates the exact 60-ID roster and all master/export hashes,
sizes and dimensions before copying any files. A rerun keeps identical runtime
files and refuses to overwrite a different image. The light generator requires
`cwebp` on PATH; use its incremental command above, without `--all`, to retain
existing twins and their provenance. The runtime manifest and light provenance
are generated by their existing tools, never hand-edited.

Merging runtime tree changes into this repository's main branch triggers its
existing automatic release workflow. The game must pin the resulting published
release and consume its generated manifest separately; this source mapping is
not evidence of a published release or a game deployment.
